# Confidentiality

Everything drafted here leaves the user's employer and reaches strangers, and a sent document cannot be retracted. When a call is close, take the more cautious option. Then apply the last section so caution doesn't hollow out the material.

The user's own specifics (their employer's internal names, their field's vocabulary, what has already been announced) live in their Rules File, section 5. This file is the general method.

## The absolute rule

No forward-looking internal specifics in any document that leaves the employer, at any tier, in any format: no dates, deadlines, sequencing, named dependencies, systems being replaced, interim workarounds, unannounced roadmaps, or next-release capabilities. "A key supplier changed its terms" is the whole statement. "We'll switch suppliers once X is done" never appears, even when the user says it in conversation.

Sanctioned shape for a change-of-plans story: "A key supplier changed its terms mid-project, which forced a new plan. I set out the workable options with the people affected, weighed cost and timing, and chose the one that kept customers whole, accepting extra work later."

## The three swaps

1. **Swap the exact count for the shape.** Ask of every number: does it size the thing or measure its performance? Is it round, or precise? Could an outsider do anything with it? Only figures in the bank's Part C marked "paper" go on a page, matching the bank exactly, rounding included. A scale figure appears once per resume (the gate counts them). Dollar figures and cost-avoidance amounts follow the Rules File, section 4; when unset, keep them off.
2. **Swap the plan for the constraint.** See the absolute rule.
3. **Swap the internal noun for the user's problem.** Internal system, project, and team names become what they do for whom ("a scheduling tool for clinic front desks", "a weekly sales report for store managers"). The user's own swap list is in their Rules File, section 5. When a word like "company" or "client" could mean either the employer or a customer, name the employer.

## Two more rules

4. **Never criticize another team, an internal decision, or a failed internal attempt.** Sanctioned shapes: "I set up the tracking myself"; "a first version that left some cases uncovered". Describe a thing that wasn't built by what the work called for, never by what was wrong with an earlier choice. Never describe a team's makeup, headcount, funding, or missing roles; "a cross-functional team" says enough.
5. **What stays in. Do not over-sanitize.** The test is non-obvious, not internal. Round scale figures the bank cleared, the shape of the problem, the decision the user made and its cost, plain-English technical facts (moving an old desktop tool to the web), the firsts the bank cleared, the tools they used. The failure to avoid is a resume that is perfectly safe and says nothing.

## Always excluded, every tier

Customer, client, coworker, and manager names. Account data or personal information. How any security control works. Vendor contract terms, vendor and framework names where the Rules File says so. Internal application, platform, and project code names. Ticket numbers. Org headcount and cost-center detail. Anything about the user's accommodations, health, or office-attendance situation. Regulatory rule numbers and "regulators require" framings (say what the user did).

## Domain tiers

Assign the tier before writing (Rules File, section 5). The tracker's Domain Tier is a starting point, not the answer: a company with no field set never gets Tier 1 from the kit, so if the posting or company is clearly in the field of the user's current job (`fit_scoring.SAME_DOMAINS` in criteria.json), use Tier 1 and say so in one line. **Tier 1, same field as the employer:** no timing at all, generalize every count unless the card's Cleared line and Part C clear it for paper or the user rules otherwise for this application, no internal product names, never characterize another team. **Tier 2, adjacent field:** timing rule absolute, scale numbers fine, translate vocabulary. **Tier 3, outside the field:** timing rule absolute, scale numbers stay, plain-English translation is the main job. The timing rule never relaxes at any tier.

## The cut test

For every sentence carrying proprietary detail: cut the detail and read it again. If it still proves the user can do the job, the detail was never doing the work. Cut it.
